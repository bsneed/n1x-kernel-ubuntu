# Review: n1x-kernel-ubuntu, exit gate of `bsneed/review-fixes`

## Summary

The branch fixes all 21 findings of the initial review. The fixes are real: each one I
checked holds in the code and has a test. 264 tests pass and shellcheck is clean. The new
nvidia-persistenced override, the scoping of 0010 and the CI changes are correct. The
branch **does not pass the exit gate**, because this round found new correctness issues in
`--remove` and in what happens after a failed install:

- **G1 (blocker, a regression from main):** `--remove` can't restore a machine that already
  had Ubuntu's NVIDIA 620 before the install. The install now records only the packages it
  replaced, so `--remove` removes the user's own 620 packages too.
- **G2 (should-fix, also on main):** `previous-kernel` is a frozen release. After Ubuntu
  autoremoves that kernel, `--remove` and every `install.sh` re-run die.
- **G3 (should-fix):** on stock GRUB, a failure after the apt transaction leaves the untested
  kernel as the boot default.
- **G4 (should-fix):** `--remove` changes GRUB's default last, so a failure partway through
  can leave the default on 7.3 after its NVIDIA modules are already gone.

None of these makes a machine unbootable: each one either stops before changing anything,
or still leaves a kernel that boots on the EFI framebuffer.

## Findings

### G1 — Blocker (correctness, regression from main) — `--remove` removes the 620 packages that were installed before the install

- **Location:** `scripts/install.sh:117`, `scripts/lib-nvidia.sh:47-59`, `scripts/install.sh:174-189`.
- **Violated requirement:** README "Remove" and docs/install.md:65: "reinstalls the NVIDIA
  packages that were there before". `nvidia_restore_removals`'s own contract (lib-nvidia.sh:49)
  says BEFORE holds "what the install replaced or found".
- **What happens:**
  - `nvidia-before` is now filtered to `$TMP/allowed`, the packages the install removes.
  - On main it held every NVIDIA package (`nvidia_installed`), so pre-existing 620 packages
    were kept.
  - On a machine that already ran Ubuntu's 620 (from -proposed), the install replaces only
    `nvidia-dkms-620-open`, so that is all `nvidia-before` holds.
  - `--remove` then wants `nvidia-dkms-620-open` and removes every other installed 620
    package, `nvidia-kernel-common-620` and `nvidia-kernel-source-620-open` among them.
    `nvidia-dkms-620-open` depends on both (verified with `apt-cache show`).
- **Evidence:** reproduced at the helper level (see Probes). The apt failure is inferred
  from the Depends.
- **Failure scenario:**
  1. A user already on Ubuntu's `nvidia-driver-620-open` runs `install.sh`. This is a case the
     code expects: `nvidia_other_versions` special-cases `nvidia-dkms-620-open`, and the
     t-nvidia fixture contains it.
  2. `sudo bash scripts/install.sh --remove` rewrites the pin (install.sh:179-181). The
     simulation then fails, so `--remove` dies. It can't succeed on any re-run without
     hand-editing `/var/lib/n1x-kernel-ubuntu/nvidia-before`.
  3. Had apt been able to resolve it, the user would have been left with no 620 user space or
     firmware.
- **Fix:** at the first install, also record the BRANCH packages that are already installed:

  ```bash
  { cat "$TMP/allowed"; nvidia_restore_removals "$BRANCH" "$NV_DKMS" /dev/null <<<"$installed"; } >"$TMP/recorded"
  ```

  Then write `nvidia-before` from `$TMP/recorded`, or record every NVIDIA package as main did.
  `want` then includes 620 packages that are already present, which is a no-op for apt. Move
  that selection into lib-nvidia.sh and add a test of the install-to-remove round trip with
  pre-existing 620.

### G2 — Should-fix (correctness, pre-existing on main) — `previous-kernel` stays pinned to a kernel Ubuntu will autoremove

- **Location:** `scripts/install.sh:86-95`, `:169`, `:213`.
- **Violated requirement:** README "Remove" and docs/install.md:70: "points GRUB's default back
  at the kernel that was running at install time". The fallback described at
  docs/install.md:38-43 is also affected.
- **What happens:** `linux-image-7.0.0-1026-nvidia` is auto-installed through the
  `linux-nvidia` metapackage. Once a newer linux-nvidia (e.g. 1030) is installed, apt's
  kernel protection keeps the running kernel and the two highest versions, which are
  7.3.0-n1x1 and 1030. So 1026 becomes autoremovable, and `apt autoremove` or
  unattended-upgrades removes it. `Remove-Unused-Kernel-Packages` defaults to `True`.
- **Failure scenario:** a month after install, Ubuntu ships linux-nvidia 1030 and
  unattended-upgrades removes 1026. Then:
  1. `--remove` dies with "previous kernel 7.0.0-1026-nvidia is no longer installed" and
     offers no way forward.
  2. `install.sh` re-runs, needed for any new N1X or NVIDIA_N1X revision, die at :94-95 with
     "has no headers … sudo apt install linux-headers-7.0.0-1026-nvidia". That message points
     at the wrong fix.
  3. If `--default` was never run, `saved_entry` names a menu entry that no longer exists.
     GRUB then boots entry 0, which is 7.3, so the "falls back to the old kernel" safety net
     is silently gone.

  Main had the same frozen value. The branch made re-runs fail earlier and more safely, but
  not correctly.
- **Fix:** when the recorded kernel is gone (no `/lib/modules/$prev/build`, or no vmlinuz),
  fall back to the newest installed `ubuntu_nvidia_kernel`, say so, and update
  `previous-kernel`. In `--remove`, also drop from `want` any `linux-modules-nvidia-*-<k>`
  whose kernel `<k>` is no longer installed; the `linux-modules-nvidia-615-open-nvidia`
  metapackage brings the current ABI. Test with a fake `MODULES_ROOT`.

### G3 — Should-fix (safety, F3 incomplete) — on stock GRUB, a failure after the apt transaction makes the untested kernel the default

- **Location:** `scripts/install.sh:125-140` vs `:137` and `:149`; docs/install.md:26-27.
- **Violated requirement:** F3's goal, and docs/install.md:26-27: "it stops with an error
  before touching GRUB".
- **What happens:**
  - `GRUB_DEFAULT=saved` and `grub-set-default $prev` happen only after every package step.
  - The kernel .deb's postinst hook (`zz-update-grub`) has already regenerated grub.cfg with
    7.3 as the newest entry.
  - With Ubuntu's stock `GRUB_DEFAULT=0` (the non-proart-p16-linux route the README mentions),
    entry 0 is now 7.3.
  - Any `die` or `set -e` exit after the apt transaction leaves 7.3 as the permanent default,
    with no one-time-boot fallback. That covers the fatal DKMS build for the fallback kernel
    (the F5 case), `update-initramfs`, `daemon-reload`, and `grub_verify`.
- **Failure scenario:** on a non-P16 N1x laptop with stock GRUB, the DKMS build fails for
  linux-nvidia. `install.sh` stops and says "GRUB was not changed". The user reboots before
  running `--remove`, and every boot goes to 7.3. If 7.3 hangs on that machine, the user has
  to pick the old kernel by hand from Advanced options. That kernel has no NVIDIA driver,
  because 615's prebuilt modules are already gone.
- **Fix:** move `grub_use_saved`, `update-grub` and `grub_point set-default "$prev"` (prev's
  entry exists already) to just before the apt transaction. The kernel's own update-grub then
  keeps `saved`, and every later failure leaves prev as the default. Correct the
  docs/install.md wording and the die message at lib-install.sh:139.

### G4 — Should-fix (safety) — `--remove` moves GRUB's default back only at the very end

- **Location:** `scripts/install.sh:189-213`.
- **What happens:**
  - The NVIDIA restore (install.sh:189) removes our DKMS package, and its prerm removes the
    modules for every kernel, 7.3 included.
  - GRUB's default is pointed back at prev only at :212-213.
  - Between the two come `update-initramfs`, `persistenced_drop`, `grub_default_get` (which
    can die), the cmdline and GRUB_DEFAULT edits, the purge (G6) and `update-grub`. A failure
    in any of them leaves `saved_entry` on 7.3 when `--default` was used.
- **Failure scenario:**
  1. The user ran `--default`, then `--remove`.
  2. `update-initramfs -u -k all` fails, for example on a full separate /boot (TODO.md:93
     already notes there is no free-space check).
  3. The next boot runs 7.3, with no NVIDIA modules for it (615's prebuilt modules exist only
     for linux-nvidia): there is no GPU driver, only the EFI framebuffer.
- **Fix:** right after the `previous-kernel` checks in `do_remove`, run
  `grub-editenv - unset next_entry` and `grub_point set-default "$prev"`. Keep the final
  set-default after update-grub.

### G5 — Nit (error handling) — `--remove` rewrites the pin before its simulation

- **Location:** `scripts/install.sh:179-186`.
- **What happens:** when `nvidia-dkms-620-open` is in `want`, the `-1` stanza is dropped from
  `$PIN` before `apt_simulate`. If the simulation fails (as in G1), the message says "nothing
  was changed", but the pin no longer blocks Ubuntu's DKMS package. The impact is low: our
  package's Conflicts/Provides still keep it out on a plain `apt upgrade`.
- **Fix:** save the old pin and put it back if the simulation fails, or reword the message.

### G6 — Nit (error handling) — steps that fail without a message

- **Location:** `scripts/install.sh:129`, `:192`, `:209`.
- **What happens:** `update-initramfs` (install and remove) and the kernel purge run bare
  under `set -e`. A failure exits with only apt's or update-initramfs's own output, and
  nothing says what state the machine is in or that a re-run is safe. Every other step has a
  `|| die "…"` message.
- **Fix:** add `|| die "…; run install.sh --remove again"` to each of them, as at :125 and
  :189-190.

### G7 — Nit (semantic) — check.sh reports OK while a stale override of ours still shadows a fixed unit

- **Location:** `scripts/check.sh:111-113`.
- **What happens:** once Ubuntu's unit drops the cycle line, check.sh prints "the packaged
  unit has no backlight ordering cycle" (OK). It doesn't look at whether our generated copy
  of the old unit is still in /etc and overriding the new one. That stays true until the
  next `install.sh` run.
- **Fix:** in that branch, WARN if `persistenced_is_ours "$PERSISTENCED_OVERRIDE"`
  ("stale override: run install.sh").

## What's Done Well

- **The persistenced override is careful:**
  - it is generated from the installed unit rather than shipped;
  - it is marked and owned, so an override the user wrote is never touched;
  - it is written atomically and dropped once the packaged unit no longer has the cycle;
  - it is removed by `--remove`;
  - it is checked by check.sh, and the fixture test keeps the unit's trailing blank line.
- **0010 is scoped by PCI ID**, so GB10 keeps NVIDIA's behaviour, and the doc now says what
  the 615 claim rests on.
- **Simulating every apt transaction first** and refusing unexpected removals or versions
  (`apt_sim_check`) turns the riskiest step into a refusal that changes nothing.
- **The F1, F2 and F5 fixes came with before/after evidence:** their tests failed on main's
  behaviour before the fixes.
- **The GRUB parsing refuses what it can't edit** (indented or exported assignments, drop-ins,
  shell expansions) instead of guessing, and the refusals are tested.
- **CI:** actions are pinned by commit, with read-only permissions.
